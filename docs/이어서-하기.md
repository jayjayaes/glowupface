## 사이트 상태

**히어로 영상만 빠졌고 나머지는 완성이다.** 지금 열어도 온전한 사이트다.

영상이 없는 동안 히어로 배경은 CSS와 SVG로 그린 "내려오는 빛" 장면이 맡는다.
임시방편이 아니라 승인된 컨셉과 같은 장면을 코드로 그린 것이다.

- 스크럽 장치 전부 구현. 밴드 4개, 진행도 구동, 게이트된 seek, 변화시에만 DOM 쓰기
- 시그니처 **금척**(세로 금색 눈금자), 누르고 있기 인터랙션, 9개 섹션, 폼까지 동작
- 전자책 표지 두 장이 실물 그대로 들어가 있음

## 영상이 생기면 할 일 (딱 두 줄 바꾸면 산다)

`sites/smlab/index.html` 자바스크립트 맨 위:

```js
var HAS_VIDEO   = false;   // → true
var VIDEO_BYTES = 6000000; // → 실제 파일 바이트 수
```

그 전에:

1. **크레딧 확인.** `balance` 호출. 보류 시점 잔액 1.26 (무료 플랜)
2. **시작 프레임 생성** (약 2 크레딧). 프롬프트는 `review/smlab/prompts.md` 1번
3. **직접 검사.** 상표, 검은 패널, 왼쪽 3분의 1의 잔잔함(캡션 자리), 금색 결
4. **사용자 승인**
5. **영상 모델 선택.** `get_cost` 는 무료. 조회해서 실제 가격으로 제시할 것
6. **영상 생성** → ffmpeg로 프레임 뽑아 직접 검사 → **영상 게이트**(사용자가 직접 봄)
7. **Phase 7 처리.** 명령은 `review/smlab/prompts.md` 5번. 스크럽 인코드는 `-g 8` 필수
8. **가독성 재측정.** 배경이 밝아지므로 밴드별 최악 픽셀 대비를 다시 잰다.
   현재 값(CSS 배경 기준): 밴드1 13.31 / 밴드2 13.23 / 밴드3 13.23 / 밴드4 9.52 (기준 3.5)
9. **Phase 10 배포**

필요 크레딧: 아끼면 약 14, 최상위 모델이면 약 60.

## 카피 규칙 (사장님 지정)

1. 마침표를 쓰지 않는다
2. 애매한 길이는 `<br>` 로 두 줄로 나눈다
   **줄바꿈은 어떤 화면에서도 숨기지 않는다.** 마침표가 없으므로
   `<br>` 이 문장의 유일한 구분이다. 숨기면 두 문장이 붙어버린다
3. 한 토막은 휴대폰에서 한 줄에 들어오게 짧게 쓴다 (한글 18자 안쪽)
   길면 마지막 단어가 혼자 떨어져서 지저분해 보인다
4. 사람 말투, 해요체 기반. AI 티 나는 표현 금지
5. 히어로 짧은 문장만 반말 (슬로건이라서)

## 자체 검사에서 실제로 잡아 고친 것

1. 구글 폰트가 렌더링을 막아 자바스크립트가 아예 안 돌던 문제 → 비차단 로딩으로
2. `form.name` 이 입력칸을 가려 폼이 이름을 못 읽던 버그 → id로 직접 접근
3. 한글에 모노 서체가 붙어 자간이 벌어지던 문제 → 본문 서체 + 자간
4. 한글이 단어 중간에서 줄바꿈되던 문제 → `word-break:keep-all`
5. `.brand span` 선택자가 브랜드명까지 숨기던 버그 (작은 화면)
6. 빛줄기 아래쪽에 하드 엣지가 보이던 문제 → 세로 마스크 추가
7. 없는 영상 파일을 불러 콘솔에 404가 찍히던 문제 → `HAS_VIDEO` 스위치
8. 순서 칸이 왼쪽에만 몰려 오른쪽이 비던 문제 → 두 단 그리드
9. 누르고 있기가 실제 마우스로는 반응하지 않던 버그
   → pointerdown 하나에만 기대던 것을 mousedown, touchstart 까지 받도록
     고치고 pointerdown 의 무조건 preventDefault 를 걷어냈다
10. **좁은 화면에서 줄바꿈을 숨겼다가 두 문장이 붙어버린 사고**
    → 마침표가 없는 카피에서 `<br>` 을 숨기면 안 된다. 규칙으로 못박음
11. 휴대폰에서 마지막 단어가 혼자 떨어지던 곳들 → 문장 토막을 짧게 다시 씀
12. 휴대폰 히어로 위쪽이 텅 비어 보이던 문제
    → 글자를 아래에 앉히고 위쪽은 내려오는 빛이 채우게 (컨셉과 같은 구성)
